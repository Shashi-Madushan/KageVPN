# U4 WireGuard: Code Generation Plan
Round 4, pull request 1 (last unit). Implements the approved functional design in `construction/u4-wireguard/functional-design/` (rules R1 to R12, flows F1 to F7). This plan is the single source of truth for U4.

## Context
- **Connect path** (`session.rs`): resolves the engine binary (`core::resolve`), runs the pre-connect check for the chosen server, picks the nodes (auto group or all), then `config::build` and `singbox::check`. The engine's build tags come from `core::inspect` (runs `sing-box version`, fast).
- **Config builder** (`config.rs:108`): the only caller of `Profile::outbound`.
- **Import dialog** (`ImportDialog.svelte`): `isConfig` decides whether Import is enabled for non-link text; `loadFile` reads a dropped file.
- Reuses U1 to U3: `over_udp`, `import_note`, `parse_all` notes, `null_as_empty`, number-or-text fields (as Hysteria speeds), the untouched-port rule.

## Steps
- [x] 1. **Server kind and build feature on every protocol** (`profile/mod.rs`, all protocol modules): `ProtocolDef::kind() -> ServerKind` (required, like `over_udp`, so a new protocol must decide) and `ProtocolDef::feature() -> Option<&'static str>` (`with_quic` for Hysteria2, Hysteria, TUIC; `with_wireguard` for WireGuard; `None` otherwise). `Profile::outbound(tag)` keeps its name and now documents "the server's config entry, outbound or endpoint"; `Profile::kind()` helper.
- [x] 2. **Config placement** (`config.rs`): split node entries by kind into `outbounds` and `endpoints`; write `endpoints` only when not empty; the `proxy` group lists all node tags in the same order. Tests in `tests/config.rs`: a mixed list puts WireGuard in `endpoints`, the selector lists its tag, no `endpoints` key without WireGuard.
- [x] 3. **Engine features at connect** (`profile/mod.rs` or a small `config::usable_nodes`, `session.rs`): pure `usable_nodes(nodes, tags: Option<&[String]>) -> (kept, left_out)` and `missing_feature_message(profile)`; `session::connect` inspects the engine once, stops with the R9 message when the chosen server is left out (before ports, pre-check or any privileged step), logs a line for the others, and builds from `kept`. Tests: tags unknown keeps all; missing `with_wireguard` drops only WireGuard; chosen-server case returns the message; auto mode same.
- [x] 4. **Module** (`profile/wireguard.rs`, new): `WireGuardSettings` per domain-entities.md (`mtu`, `keepalive` read from number or text; `reserved: Option<[u8; 3]>` read from numbers, a list, or 3-byte base64; optional texts with `null_as_empty`); `impl ProtocolDef for WireGuard`:
  - `id` `"wireguard"`, `label` `"WireGuard"`, `schemes` `["wireguard", "wg"]`, `over_udp` true, `kind` `Endpoint`, `feature` `with_wireguard`.
  - `parse` / `to_link` (R1.1, R2), `validate` (R3 key, address, MTU, reserved checks), `outbound` (the endpoint entry of F3, `system: false`, `allowed_ips` everything), `identity` (R6), `secrets` (R7), `summary` ("WireGuard" or "WireGuard · WARP" when reserved bytes are set), `form` (frontend-components.md), `blank` (port 51820, MTU 1408), `normalize` (F7), `sample()`.
- [x] 5. **wg-quick reader** (`profile/wireguard.rs`, `profile/links.rs`): `parse_wg_quick(text, name_hint) -> Result<(Profile, Option<note>)>` per R1.2, R3, R4, R5 (sections, `Key = value`, comments, `# Name =`, several `Address`/`AllowedIPs` lines or comma lists, AmneziaWG keys refused, multi-peer refused). `parse_all` checks for wg-quick text after JSON and YAML and before link splitting; `parse_all` gains an optional name hint (`parse_all_named(text, name)`; `parse_all` stays as is for other callers).
- [x] 6. **Subscriptions** (`profile/formats.rs`): read sing-box `endpoints` as well as `outbounds`; `type: wireguard` in either (new `peers` form and old single-peer outbound form: `server`, `server_port`, `local_address`, `private_key`, `peer_public_key`, `pre_shared_key`, `reserved`, `mtu`); Clash `type: wireguard` (flat form and `peers:` list; more than one peer refused). Each becomes a `wireguard://` link (R1.3, R1.4). The "groups are ignored" list does not change.
- [x] 7. **Import command and dialog** (`commands.rs`, `src/lib/api.ts`, `src/lib/app.svelte.ts`, `ImportDialog.svelte`): `import_text` takes an optional `file_name`; the dialog recognises wg-quick text in `isConfig`, remembers a dropped file's name (cleared when the text is edited), accepts `.conf` files, and mentions `wireguard://` and `.conf` in its placeholder.
- [x] 8. **Shared tests that assumed outbounds** (`tests/profile_conformance.rs`, `tests/profile_formats.rs`): the address check reads `peers[0]` for endpoints; the sing-box round trip writes endpoints under `endpoints`.
- [x] 9. **Tests** (`tests/profile_wireguard.rs`, new, plus additions): link forms and parameter spellings; `+` restored in keys; reserved in each spelling; defaults; every R3 refusal with its message; wg-quick files (WARP export, a commercial VPN export with DNS and narrower AllowedIPs giving a note, `# Name`, file-name hint, multi-peer, AmneziaWG, missing Endpoint); round trip; endpoint entry shape; identity ignores the local address; sing-box (both forms) and Clash (both forms) subscriptions; `health.rs` (UDP); demo mock `new_profile` knows WireGuard.
- [x] 10. **Runtime checks on a spare port** (R11, NFR2): `sing-box check` passes the sample and a WARP-style entry (in the conformance and config tests). Then, outside the test suite, run sing-box 1.14.2 directly in Proxy Only mode on spare ports (not 2080 or 19090) with a WireGuard endpoint pointing at a documentation address, call the Clash API `/proxies/node-…/delay`, and confirm it answers (a timeout is the expected result for an unreachable peer, not "not found"). Stop that sing-box afterwards. If the endpoint is not listed by the Clash API, latency for WireGuard shows "not available" (front end), and this step records it.
- [x] 11. **Screenshot fixture and docs**: regenerate `protocols.json`; `ADDING-A-PROTOCOL.md` (WireGuard row, `kind`, `feature`), README, docs site (import list incl. `.conf`, a WireGuard page and navigation entry, changelog lines for WireGuard and for the missing-engine-feature message), wording that lists protocols; `aidlc-docs/construction/u4-wireguard/code/summary.md`.
- [x] 12. **Verify**: `cargo test --lib -- --test-threads=4`, `cargo clippy --all-targets -- -D warnings`, `npm run check`, `npm run test:scripts`, `npx vite build`; the Add server dialog and WireGuard editor in the screenshot demo (headless, spare port). No live-app run against your real VPN.

## Results and decisions made while coding
- **Latency (step 10):** sing-box 1.14.2 on spare ports 21080/29090 listed the endpoint in the Clash API (`node-wg`, type WireGuard) and `/proxies/node-wg/delay` answered `Timeout` for an unreachable documentation peer, the same as any server. No "not available" case was needed. The test sing-box was stopped and both ports were free afterwards.
- **sing-box files:** besides WireGuard, an entry of a type Kage does not run (such as a Tailscale endpoint) now says "<type> servers are not supported yet" instead of "no server address".
- **Editor polish from the demo check:** keepalive 0 is saved as null so the field shows empty ("Off"); a shorter reserved-bytes placeholder; the Add server dialog says "WireGuard file: its server will be added".
- **`parse_all` is no longer re-exported** (only tests and `parse_all_named` use it).

## Interfaces added
`ServerKind`, `ProtocolDef::kind`, `ProtocolDef::feature`; `profile::wireguard::{WireGuard, WireGuardSettings, ID}`; `parse_all_named`; `usable_nodes`; `import_text` optional `fileName`; config may contain `endpoints`.

## Out of scope
Multi-peer WireGuard, AmneziaWG, using the `.conf` DNS or AllowedIPs, WireGuard as a system interface (`system: true`).
